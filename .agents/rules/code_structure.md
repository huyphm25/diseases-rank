# Code Structure & Refactoring Guidelines

When writing or building new code, follow these principles to ensure the codebase remains maintainable and easy to refactor:

1. **Separation of Concerns**: Always separate distinct logic into modular functions and classes. 
2. **Avoid Monoliths**: Do not write large, monolithic scripts or functions. Break complex tasks down into smaller, testable helper functions.
3. **Class Encapsulation**: Group related state and behavior into classes. 
4. **Modularity**: Design components so they can be easily moved, swapped, or refactored later without breaking the entire system.
